# Ava Training Program - Wholesale Real Estate Closer

This file is the PBK-approved training objective for offline evaluation and future manual fine-tuning. It is intentionally safe: it prepares and evaluates candidate improvements, but it must not auto-promote a model, change Render environment variables, disable approval mode, or send provider actions.

## Goal

Improve Ava's ability to:

1. Detect BANT signals from seller speech:
   - Budget: what number makes the seller comfortable.
   - Authority: who can sign and who else must approve.
   - Need: why they are selling.
   - Timing: when they want to close or be contacted next.
   - Urgency: what happens if they do not sell in the next 90 days.
2. Recommend the correct PBK path:
   - cash-offer: seller prioritizes speed, certainty, as-is cash.
   - creative-finance: seller is open to payments, monthly income, or better total price through terms.
   - mortgage-takeover: low equity, existing low-rate debt, subject-to/sub-to opportunity.
   - rbp: retail buyer program when retail spread supports a higher seller net.
   - land: land owner with feasibility contingency.
   - land-agent: land or listed deal with an agent involved.
3. Handle objections using PBK memory and approved scripts:
   - price is firm.
   - I need to talk to my spouse/family.
   - is this a scam.
   - I got a higher offer.
   - call me later.
4. Recall memory before major decisions:
   - call `pbk_recall_memory` before recommending path, contract, offer movement, or follow-up timing.
5. Avoid repeated questions:
   - if BANT or seller preference already exists in memory, acknowledge it and move forward.

## Training Data

Use `.pbk-training/ava-training-data.jsonl`, generated by:

```bash
npm run ava:training:export
```

Each JSONL row contains:

- system: Ava's PBK role and guardrails.
- user: transcript snippet plus optional lead/call context.
- assistant: approved human-reviewed action.
- metadata: feedback id, lead id, call id, agent name, decision, and timestamp.

## Success Metrics

Use a held-out review set when enough examples exist. Candidate improvements must beat the current baseline by at least 5 percent on one primary metric without regressing the others.

- BANT extraction accuracy target: 85 percent or better.
- Correct PBK path recommendation target: 90 percent or better.
- Repeated question reduction target: 50 percent reduction.
- Unsafe provider-write attempts target: 0.
- Wrong contract path target: under 5 percent.

## Safety Guardrails

- Keep `allowProviderWrites=false` until manual launch criteria are met.
- Keep all calls, SMS, email, and contracts approval-gated.
- Never auto-write a fine-tuned model id into Render.
- Never auto-deploy a candidate model.
- Never train on rejected, private, or ambiguous feedback unless a human explicitly promotes it into approved examples.
- Never include full sensitive seller records outside the PBK-controlled private runtime.

## Manual Promotion Criteria

A model or skill change can be promoted only after:

- 100 consecutive approval-reviewed interactions show at least 95 percent correct path selection.
- 20 email/SMS/contract drafts are manually reviewed without serious errors.
- Deepgram transcript/sentiment proof is clean on answered calls.
- DocuSign production path is intentionally enabled and tested.

## Output

Candidate systems should write only candidate artifacts, for example:

- `.pbk-training/best_model.txt`
- `.pbk-training/eval-report.json`
- `.pbk-training/skill-candidates/*.md`

Human approval is required before any candidate is wired into production.
