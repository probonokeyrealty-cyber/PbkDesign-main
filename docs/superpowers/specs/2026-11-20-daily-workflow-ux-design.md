# PBK daily workflow UX

The founder chose to modernize the daily workflow first. This design covers the first release slice of the Command Center modernization. Implementation awaits design approval.

## Goal

An operator should be able to start on Today, find a lead, inspect that lead's saved property record, comps and photos, and open Deal Analyzer with the same lead in view. Returning should take them back to the work they were doing. Use the existing dark PBK visual identity, typography, desktop sidebar, mobile bottom navigation, and shared bridge.

The original Claude design favors a list-first workspace, a stable record identity, and a clear separation between saved evidence and actions. Claude's subsequent critique recommends a single contextual call action on Today, which the app already has. Reuse that surface and its status rather than introduce another call card. [Original Claude conversation](https://claude.ai/chat/1f94828f-e766-4a2c-82c7-82463c84b05e) · [Claude UX critique](https://claude.ai/chat/a1c24332-d7a8-45ae-90ac-4ac7c5ee493a)

## Approaches

1. **Daily workflow first, selected.** Improve the four existing screens together and use their interactions to establish patterns for later pages. This improves a complete job while the wider navigation remains familiar.
2. **Shared navigation first.** Group destinations and standardize navigation before changing individual workflows. This helps discovery across the app sooner. Operators would still have the current gaps between the queue, property evidence, and Analyzer.

## First release slice

| Surface        | Operator experience                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Today          | Keep call and approval status visible. Put the Work queue and Review shortcuts beside the header summary. Add a plainly labeled **Browse leads** link to the existing full roster. Opening a queue item uses the current exact-ID handoff and restores queue context on return.                                                                                                                                                                                                                        |
| Leads          | Keep search, filters, result state, and the full roster together. Make **Open lead** the clear row action using the existing lead link. On narrow screens, lead identity and the action lead the row. Keep filters reachable and preserve current pagination, selection and queue return behavior.                                                                                                                                                                                                     |
| Lead workspace | Put **Property record**, **Saved comps**, and **Property photos** together in the existing workspace section navigation. Show the property address and lead ID with that navigation. Use the same hashes Ava uses for saved evidence. Show evidence availability from persisted data only. Keep the existing viewer, source timestamps and selection controls. Distinguish **Refresh lead** from **Refresh property intelligence**, and give the latter a separate action position.                    |
| Deal Analyzer  | Add a compact lead context and **Back to lead** link to the existing lead-bound Analyzer wrapper after exact-ID verification. Carry the original workspace return context through the link. If there is no validated prior evidence tab, land on the lead overview. Keep standalone Analyzer, draft behavior, calculators and save flows as they are. The handoff should say **Open Deal Analyzer** because opening it reads saved inputs. The Analyzer's existing **Analyze** action starts analysis. |

Apply common labels and a consistent visual order across the four surfaces. Use the existing components and tokens, with a single prominent action in each workflow section. Where data is unavailable, show that state in text and use existing error and retry behavior. On mobile use full-width search, wrapping IDs and labels, visible focus, and 44px targets for the new workflow links. Maintain keyboard access to existing tabs, scroll-to-section destinations, and photo controls.

## Contracts and limits

- Keep the current routes, deep links, lead lookup contracts and approval gates. Opening any saved view, switching leads, following an Ava voice command, opening Analyzer, and returning to a queue use existing read paths for CRM and property data. Preserve existing Analyzer draft persistence during lead hydration. Explicit **Refresh property intelligence** and **Analyze** retain their current provider behavior. Keep the existing explicit comp and photo actions.
- A saved-evidence link always names the selected canonical lead ID. Reuse `readLeadEvidenceTarget` and the current property tab and stale-response guards. Preserve the existing `leadReturn` validation for Today and Leads and the existing validated Fleet origin when present. Limit Analyzer return state to the verified lead, the existing known evidence target, and those existing return shapes. A direct Analyzer link can return to the verified lead overview without origin state.
- Preserve the original context after refreshed or delayed responses and while changing rapidly between leads. Use confirmed data for status copy. No new storage, provider connection, action permissions, agent workflow, or external writes are part of this slice.
- Existing sidebar labels and bottom destinations stay in this slice. Later passes apply the same hierarchy to Inbox and Campaigns, then Fleet, Memory, Skill Studio, Analytics and Settings, using each page's existing patterns and permissions. The separately routed investor portal keeps its existing release and access rules.
- The builder can choose the exact responsive layout, which existing controls to reuse, and how to compose the route state. Keep detailed screen copy short and use accessible names where icons appear without labels.

## Acceptance checks

- In a browser with two synthetic leads, open one lead from Today and another from a filtered Leads roster. For each, verify the address and ID, distinct saved comp and photo content, and correct Analyzer identity. Return to the originating lead and queue with supported filter, page, focus and scroll state restored. Cover direct evidence links and the legacy Analyzer aliases.
- Run the existing Ava two-lead evidence regression for **Show saved comps** and **Open property photos**. Exercise the new navigation with request interception. Assert zero property refresh or Analyze requests during saved evidence navigation and zero refresh calls when opening Analyzer. A single explicit Refresh on a test fixture must reach the existing endpoint for that same lead. Verify saved views still work if a refresh fails.
- Check desktop and 390px and 320px widths for overflow, focus visibility, tab order, and existing photo controls. Run typecheck, build, shell and mobile checks, and lead/Analyzer browser coverage. Validate the built app against the existing bridge contract with synthetic records. Production publication requires separate release instructions.
